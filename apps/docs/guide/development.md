# Разработка

В проекте **два независимых режима запуска**. Это не одно и то же и решают они разные задачи — важно не путать.

## Требования

- **Node.js ≥ 24** и **pnpm ≥ 11** (см. `engines` в корневом `package.json`).
- В корне репозитория лежит [`.nvmrc`](https://github.com/nvm-sh/nvm#nvmrc) с версией `24` — если у вас установлен nvm/fnm/asdf, выполните `nvm use` (или включите auto-switch), чтобы не следить за версией вручную.
- `.npmrc` содержит `engine-strict=true` — `pnpm install` **откажется** ставить зависимости на неподходящей версии Node вместо тихой установки, которая могла бы сломаться на рантайме позже.
- Версия pnpm закреплена через `packageManager` в `package.json` — при включённом [corepack](https://nodejs.org/api/corepack.html) она подхватывается автоматически, вручную ставить не нужно.

| | Режим разработки | Режим production |
|---|---|---|
| Команда | `pnpm dev` | `docker compose up` |
| Код (backend/frontend/docs) | нативно, с HMR | собран в Docker-образы |
| Доступ | напрямую: `:3000`, `:3001`, `:5173` | напрямую: хост-порты из корневого `.env` |
| Скорость правок | мгновенно (hot reload) | пересборка образа |

## Почему для разработки — НЕ Docker

Docker-образы собирают **production-артефакт** (`pnpm build`). Любое изменение кода потребовало бы пересборки образа — это десятки секунд на каждую правку, без hot-reload и удобного дебага.

Поэтому код в dev запускается **нативно** через `pnpm dev` — это быстрее и удобнее для отладки.

Такое разделение — стандартная практика: локально код нативно ради скорости, Docker собираешь только для прод-образа и деплоя.

## Режим разработки

```bash
pnpm dev
```

Одна команда поднимает всё нужное. Перед стартом отрабатывает [`predev.mjs`](/guide/env-variables#predev-mjs):

1. создаёт `.env` из `.env.example`, если отсутствуют;
2. разруливает конфликты портов.

Затем `dev.mjs` запускает три процесса нативно, каждый со своим hot-reload:

| Сервис | URL | Технология |
|---|---|---|
| Backend | `http://localhost:3001` | NestJS `--watch` |
| Frontend | `http://localhost:3000` | Nuxt dev |
| Docs | `http://localhost:5173` | VitePress dev |

## Режим production

```bash
docker compose up --build
```

Собирает и запускает полный стек — **backend**, **frontend**, **docs** — как три независимых контейнера, каждый на своём хост-порту (`BACKEND_HOST_PORT`/`FRONTEND_HOST_PORT`/`DOCS_HOST_PORT` из корневого `.env`).
